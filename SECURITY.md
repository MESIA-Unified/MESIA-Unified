# Security Policy

## Scope

This repository contains **documentation only**. The MESIA Unified engine
source code is private research and is not distributed, built, or executed
from this repository, so the usual "vulnerability in shipped code" model does
not directly apply here.

That said, a public documentation repository for this kind of project has its
own real risk classes, and reports about them are taken seriously:

- **Accidentally published sensitive material** — credentials, keys, console
  SDK material, proprietary files, or personal information committed by
  mistake (in `main`, in history, or in a pull request).
- **Suspected license violations** — content that appears to be copied from
  proprietary, leaked, or otherwise incompatible sources (this repository is
  CC BY 4.0 and only accepts original or compatibly licensed work).
- **Malicious content** — links, files, or instructions that could harm
  readers.

## Reporting a vulnerability

Please report all of the above **privately** through GitHub:

1. Open the repository's **Security** tab.
2. Select **"Report a vulnerability"** (GitHub private vulnerability
   reporting / draft security advisory).
3. Describe what you found, where, and why it is a concern.

If private vulnerability reporting is not available, contact the project
owner (@MESIA-Project) directly through GitHub.

**Do not open a public issue** for suspected sensitive material or license
problems — public discussion spreads the very content that would need to be
removed.

## What to include

- The file, commit, pull request, or URL involved
- What the material appears to be and why it should not be public
- Whether it exists on the current `main` branch, in commit history, or in
  an open pull request or fork

## Response

- Reports are acknowledged as quickly as the owner can review them.
- Confirmed sensitive material is removed promptly; history is rewritten
  where necessary, and GitHub Support may be engaged for cached views.
- You will be credited in the advisory if you wish.

## Out of scope

- **The private engine itself.** If you somehow obtain information about a
  problem in the engine, report it through the same private channel — do
  not disclose it publicly.
- **Ordinary documentation inaccuracies** — use the regular issue templates
  for those.
